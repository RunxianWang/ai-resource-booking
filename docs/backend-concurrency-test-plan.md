# 后端并发与可靠性测试方案

## 1. 目标与范围

本阶段以后端预约链路为核心，重点验证库存正确性、并发幂等、Redis/MySQL 一致性、Outbox/Kafka 消息可靠性和业务边界。前端不作为本阶段重点，只保留构建与静态检查。

测试必须使用专用 slot（默认 `990001`）、测试机器、用户和 Redis key，不能修改演示数据。每个场景都需要在测试结束后清理 fixture，并保存请求结果、数据库状态和服务日志。

## 2. 测试场景总览

| 编号 | 场景 | 重点断言 | 自动化状态 |
|---|---|---|---|
| T01 | 不同用户并发抢库存 | 成功数不超过库存，MySQL/Redis 最终一致 | 已实现并发脚本 |
| T02 | 同一用户并发重复预约 | 只成功一次，库存只扣一次 | 已实现边界脚本 |

| T05 | 数据库唯一约束和事务回滚 | 重复预约被约束，失败事务无残留 | 已实现运行态检查；现有脏数据阻塞索引 |

## 3. 一致性不变量

稳定状态下必须满足：

```text
I1: 0 <= MySQL available_count <= total_count
I2: available_count = total_count - RESERVED booking 数
I3: 同一 user + slot 最多一条有效预约
I4: Redis stock = MySQL available_count
I5: Redis booked-users = MySQL RESERVED 用户集合
```

消息收敛还必须满足：

```text
M1: 每条成功预约/取消都有对应 Outbox message_log
M2: 可发送消息最终变为 SENT，或明确进入失败/DLT状态
M3: SENT 消息最终有对应成功 consume_log
M4: 重复 messageKey 不重复更新投影和审计
```

## 4. 场景验收标准

### T01：不同用户并发抢库存

默认 fixture 为容量 100、500 个用户、并发数 100。预期 `SUCCESS=100`、其余为 `SOLD_OUT`，无系统错误、无负库存、无超卖，并满足 I1-I5 和 M1-M3。

### T02：同一用户并发重复预约

同一用户并发提交 20 次，预期只有 1 次成功、19 次 `DUPLICATE_BOOKING`；数据库只有一条有效预约，库存只扣减一次。

### T03：同一预约并发取消

同一预约并发取消 20 次，预期只有 1 次成功，其余返回幂等跳过结果；库存、Redis 用户集合和取消消息只变化一次。

### T04：最终一致性

预约和取消操作完成后等待消息收敛，查询 `/api/dev/verify/{slotId}` 及 Redis 状态。任何 I1-I5 或 M1-M3 失败都判定失败。

### T05：唯一约束和事务回滚

使用真实 MySQL 验证 `(user_id, slot_id)` 唯一约束。分别注入库存更新、预约写入和 Outbox 写入失败，确认数据库事务整体回滚，Redis 有幂等补偿，不留下半条业务记录。

### T06-T11：消息可靠性

使用真实 Kafka，验证 Outbox 发送、消费者幂等、Kafka 暂停恢复、OutboxSender 重启、重试、DLT 落库和 Replay 并发保护。Kafka 相关测试不能只通过 Mock 判定全链路成功。

### T12：业务边界

验证时长只允许 1、2、4 小时；预约必须是当天、下一整点之后、完整小时且连续可用；跨天、非连续、已占用和不存在的 slot 必须返回明确错误码。

## 5. 测试套件

```text
Fast:
  Java 单元测试
  不依赖中间件的快速回归

Full:
  Java 完整测试、前端 lint/build
  T01-T12 全部运行态检查

Resilience:
  T05-T11 的数据库、Redis、Kafka 收敛与故障恢复检查

Load:
  Full 的并发场景，并将 T01 请求数提升到指定值
```

## 6. 通过标准

- 核心并发场景无超卖、无负库存、无系统错误。
- 同一用户重复预约只能成功一次。
- 同一预约并发取消只能成功一次。
- MySQL、Redis、预约记录最终满足 I1-I5。
- Outbox/Kafka 在稳定环境下最终收敛。
- 重复 Kafka 消息不重复执行业务。
- 故障场景按预期回滚、重试、进入 DLT 或恢复。
- 测试数据可清理，失败时保留日志和状态快照。

## 7. 非本阶段重点

- 大规模前端组件单元测试。
- 完整 OWASP 安全审计。
- 生产环境容量承诺。
- 多租户、复杂权限中心和数据库迁移框架。
