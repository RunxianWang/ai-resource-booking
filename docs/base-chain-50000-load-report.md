# 50,000 请求基础压测报告

## 结论

在当前本机环境下，使用连接复用后的压测脚本完成了 50,000 次基础预约请求，业务正确性通过，客户端和后端均未出现系统错误。

测试服务：`http://localhost:8081`，`perf` profile  
测试资源：`slot=900001`，容量 100  
测试时间：2026-08-31 13:25（本地时间）

| 消息最终一致性 | PASS |

## 判断

- 本机可以完成 50,000 次请求规模的基础压测。
- 业务正确性保持通过：没有超卖、没有系统错误，库存和 Redis 用户集合最终一致。
- P50 较低，但 P95/P99 出现明显长尾，说明在高请求量下仍存在排队、数据库事务或本机资源竞争，需要进一步做 CPU、连接池、GC、MySQL 慢查询和 Redis 延迟监控，不能只根据 TPS 判断容量。
- `SUCCESS=100` 是因为测试库存固定为 100；其余 49,900 次是正常的 `SOLD_OUT`，不是失败请求。

## 测试过程中的脚本问题

第一次尝试使用每个请求新建短连接，在最终查询阶段触发 Windows `WinError 10048`，原因是本机临时端口耗尽。随后将脚本改为线程级 HTTP 连接复用，第二次测试成功完成。第二次结果才作为有效压测结果。
